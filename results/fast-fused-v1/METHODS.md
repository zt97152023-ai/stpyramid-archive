# 原生金字塔融合图像编码方法

## 数据对象与无损边界

一个图像归档保存切片的全部原生 RGB8 分辨率层及源图像元数据。每层按 256×256 分块，边缘块保留有效尺寸。L0 和 L1 的条件块从原生下一层取对齐参考，按父层真实尺寸处理边缘。L2 及更低分辨率层独立编码，使读取依赖最多跨越两级。无损核验以源 TIFF 的各层有效 RGB 数组、原生几何及源图像元数据为准。

## 低频校正与细节编码

令 `X_l` 为原生第 `l` 层目标块，`A_(l+1)` 为同一空间区域的原生下一层参考。对目标块和参考使用整数颜色变换 `C(R,G,B) = (G,R-G,B-G)`。对 `C(X_l)` 做水平和垂直可逆整数 Squeeze，得到低频 `L_l` 和细节系数。参考在低频网格上，编码器直接计算 `Δ_l = L_l − C(A_(l+1))`。读回时用精确整数加法 `L_l = C(A_(l+1)) + Δ_l` 还原低频。091 Modular 使用已解码低频和中间重建系数提供细节上下文，保存恢复目标块所需的其余系数。每块的自适应熵参数随码流保存，无离线训练。

融合路径在同一次原生编码调用中生成低频校正和细节流。预先按像素规则决定编码路径。所有 RGB 像素完全相同的块走直接 JXL e9，L0 和 L1 其余块走融合 091，L2 起全部走直接 JXL e9。相同像素和尺寸的纯色块复用编码计算，每个块的实际记录仍完整计入归档。块的索引和父层定位随归档保存。

## 整片对照

验证固定 10 张整片，包括已用于开发的 NCBI224 和来自另外 9 个 HEST 研究条目的切片。其余样本按平台配额和 L0 像素面积选出，要求有历史原方案归档、可核验源文件和符合几何约束的原生层。按平台内面积和样本 ID 排序，对标准化研究标题去重。选样不使用压缩率、计时或图块编码候选的结果。这是基于历史归档可用性的定向验证，面积偏向各平台中较小的候选。

融合版和直接 JXL e9 使用同一原始 TIFF 独立完整编码，均采用同样的纯色复用。直接 JXL 使用 effort 9、distance 0、无损模式和单线程。原 HF+L1 比较采用实际历史归档及绑定的原生运行时，读取在本次验证中重新测量。三组的成员字节与逐层像素统一核验。两组新归档的源元数据文件逐字节一致。历史对照核对相同的源 TIFF SHA-256 和图像元数据，文件系统时间戳差异单独记录。归档大小为 `images.bank`、`images.index`、`anchors.index`、`source.json` 和 `manifest.json` 的实际物理字节和。

编码计时从读入和建立源图块目录开始，到完整图像包生成结束。读回计时包含打开归档、校验归档成员、解码全部原生层以及核对逐层 SHA-256。ROI 使用同一原生层上的固定 256×256 查询窗口，记录热读中位数。每个配对固定在同一逻辑核心，样本间并行，单次全量编码和全量读回，未控制操作系统文件缓存。报告逐样本结果、配对相对变化和中位数，并保留表现下降的样本。
